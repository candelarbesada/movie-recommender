# Contributing to Movie Recommender

Thank you for your interest in contributing to Movie Recommender.

This document describes the initial contribution guidelines. These guidelines may evolve as the project grows.

## Current Project Status

Movie Recommender is currently in its initial setup and planning stages.

The product discovery phase has been completed. Architecture and technology decisions are the next planned stage.

Please avoid introducing architectural or technology decisions that have not yet been discussed and agreed upon.

## How to Contribute

1. Check existing documentation and project decisions before proposing changes.
2. Open an issue to discuss significant changes or new features.
3. Keep contributions focused and reasonably small.
4. Provide a clear description of the changes.
5. Update relevant documentation when product decisions or project requirements change.

## General Guidelines

- Use English for source code, identifiers, commit messages, and technical conventions.
- Use Spanish for product and functional documentation unless otherwise agreed.
- Follow the existing project structure and conventions.
- Avoid unnecessary complexity and premature optimization.
- Do not commit credentials, API keys, tokens, personal data, or other sensitive information.
- Prefer maintainable, readable, and well-documented solutions.

## Commit Messages

Commit messages should be concise and descriptive.

The project uses the following conventional prefixes:

- `feat:` New functionality.
- `fix:` Bug fixes.
- `docs:` Documentation changes.
- `refactor:` Code restructuring without changing behavior.
- `test:` Tests and testing-related changes.
- `chore:` Maintenance and configuration changes.
- `ci:` Continuous integration changes.

Examples:

- `docs: add product discovery documentation`
- `chore: initialize repository configuration`
- `feat: add movie search endpoint`

## Pull Requests

When pull requests are introduced into the development workflow, they should:

- Explain the purpose of the change.
- Describe relevant implementation details.
- Reference related issues when applicable.
- Include tests or validation evidence when relevant.

## Questions and Suggestions

For questions, bug reports, or improvement proposals, please use the repository's GitHub Issues section.
